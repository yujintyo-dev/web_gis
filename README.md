# 公開型GIS(GitHub Pages用)

`data` フォルダにGeoJSONを置くだけでレイヤーが追加され、表示設定は **管理画面** で編集できる公開型GISです。
データの変換は GitHub が自動で行います(自分のPCにPythonは不要です)。

## しくみ

```
data/ にGeoJSONを置く / config.json を更新する
        ↓ (GitHubに保存すると自動で)
GitHub Actions が変換 → 大きいデータは「表示範囲だけ読み込む形式」に分割
        ↓
公開サイトが更新される(数分)
```

| ファイル・フォルダ | 役割 |
|---|---|
| `data/` | ★ここにGeoJSONを置く。**フォルダ名がカテゴリ**になる |
| `config.json` | 表示設定(名前・色・ポップアップ・順序など)。管理画面が書き換える |
| `index.html` / `js/` / `css/` | 公開サイト本体(触らなくてOK) |
| `admin.html` | 管理画面 |
| `tools/build.py` | 自動変換プログラム(Actionsが実行) |
| `.github/workflows/build.yml` | 自動実行の設定 |

## 初回セットアップ

1. GitHubで新しいリポジトリを作る(Public)
2. このフォルダの中身を**すべて**アップロードする
   - 「Add file → Upload files」にフォルダ内のファイルをドラッグ&ドロップ
   - `.github` フォルダは隠しフォルダなので、ドラッグ&ドロップで入らないことがあります。
     その場合は「Add file → Create new file」で、ファイル名に `.github/workflows/build.yml` と入力し、
     同名ファイルの中身を貼り付けてください
3. **Settings → Pages → Build and deployment → Source を「GitHub Actions」** にする(重要)
4. 「Actions」タブで `build-and-deploy` が緑色になるのを待つ(初回は数分〜十数分)
5. 公開URL(`https://ユーザー名.github.io/リポジトリ名/`)を開く
   管理画面は、同じURLの末尾に `admin.html` を付けたものです

> 以前のバージョンのリポジトリを使う場合は、古いファイル(`data/layers.json`、`data/tiban_*` フォルダなど)を
> **すべて削除**してから新しい一式を入れてください。

## 手元のPC(VS Code の Live Server)で確認する

`manifest.json` と変換済みデータは**ビルドで作られるファイル**です。リポジトリ直下を Live Server で開いても動きません。

1. Python 3 をインストールしておく(python.org)
2. VS Code のターミナルで、リポジトリ直下から実行(筆界の変換に数分、メモリ約2GB):
   ```
   python tools/build.py
   ```
   `_site` フォルダができます(2回目以降は変更分だけ変換されるので速いです)
3. **`_site/index.html`** を右クリック →「Open with Live Server」
   管理画面は `_site/admin.html` です
4. `data/` や `config.json` を変更したら、もう一度 `python tools/build.py` を実行してリロード

※ 管理画面の「GitHubに保存」は、手元で開いた場合は使えません(「設定をダウンロード」で保存し、`config.json` を置き換えてください)。
※ Windowsで `python` が動かないときは `py tools/build.py` を試してください。

## 毎年のデータ更新(地番図など)

1. 新しいGeoJSONを、**今と同じ名前・同じ場所**で置き換える
   - 例: `data/地番図/筆界.geojson.gz`
2. Commit する(Upload files で上書きして Commit changes)
3. 自動で再変換され、数分〜十数分で公開サイトが更新されます(Actionsタブで進み具合を確認)

- 設定(ポップアップ・色など)は `config.json` に残っているので、**作り直し不要**です
- 属性名が変わった場合は、管理画面でポップアップなどを確認してください
- 変換に失敗したレイヤーは公開されません(他のレイヤーは影響なし)。原因はActionsのログと管理画面の左下に出ます
- 更新日は、データが変わったときの自動変換の日付が「データ更新」として表示されます
  (管理画面の「データ時点の表示」で「令和8年1月」のように書き換え可能)

## レイヤーを追加する

1. QGISで レイヤーを右クリック → エクスポート → 新規ファイルに地物を保存
   - 形式: **GeoJSON** / 座標参照系: **EPSG:4326 - WGS 84** / 文字コード: UTF-8
2. `data` フォルダの中に置く(フォルダがカテゴリになります)
   - 例: `data/都市計画/用途地域.geojson` → カテゴリ「都市計画」、レイヤー名「用途地域」
   - 例: `data/防災/洪水浸水想定/想定最大.geojson` → 階層「防災 > 洪水浸水想定」
3. Commit する → 数分後に反映(**最初は非表示**で追加されます)
4. 管理画面で名前・色・ポップアップ・初期表示などを設定して保存

### ファイルの形式とサイズ

- `.geojson` / `.json` / `.geojson.gz`(gzip圧縮)/ `.zip`(中にGeoJSON1つ)が使えます
- **100MBを超えるファイルは `.zip`(Windowsなら右クリック→「ZIPファイルに圧縮」)にして置いてください**
  (GitHubは1ファイル100MBまで。GeoJSONは圧縮すると約1/6になります)
  Web画面からのアップロードは**1ファイル25MBまで**です。それを超える場合は
  GitHub Desktop を使うか、次の「Releases」方式にしてください
- 数千件を超えるデータは、自動で分割されます(表示範囲だけ読み込むので軽く動きます)

### さらに大きいファイル(Releases方式)

1. GitHubのリポジトリで「Releases → Draft a new release」を開き、GeoJSON(または.zip)を添付して公開
2. 添付ファイルのダウンロードURLをコピー
3. `config.json` の `layers` に、レイヤーID(`カテゴリ/名前`)で `"build": {"url": "コピーしたURL"}` を書く
   (`data` フォルダにファイルは置きません)

```json
"layers": {
  "地番図/筆界": { "build": { "url": "https://github.com/…/releases/download/…/筆界.zip" } }
}
```

## 管理画面(admin.html)

左: カテゴリとレイヤーの一覧(▲▼で並べ替え)/ 右: 編集画面

- **全体設定**: サイト名、最初に表示する位置とズーム(地図を動かして決められます)
- **対応表**: コード→名称(例: 大字コード→大字名)。「コード一覧を取り込む」で、データ中のコードを一括で入力欄に出せます
- **カテゴリ**: 表示名、最初から開くか。レイヤーのカテゴリ欄に `親/子` と書くと階層になります
- **レイヤー**
  - 基本: 表示名・カテゴリ・初期表示・表示ズーム・非公開
  - 見た目: 色・太さ・塗り・属性による色分け(凡例は自動生成)・地図上の文字
  - ポップアップ: 表示する属性の選択・表示名・単位・数値/リンク形式・対応表・並び順・自由なHTML(プレビューつき)
  - ダウンロード・検索: GeoJSONダウンロードの可否、検索の設定
  - データ変換: 残す属性、点データの属性を面に取り込む設定、検索データの作成(**変更すると再変換されます**)

**画面の上下の並び順 = 地図の重なり順**(上にあるレイヤーほど手前)です。クリックすると、重なったレイヤーの情報がまとめて出ます。

### 保存のしかた

- **「GitHubに保存」**: 設定が `config.json` に反映され、数分後に公開サイトが更新されます(下記トークンが必要)
- **「設定をダウンロード」**: `config.json` を保存します。GitHub上の `config.json` を、この内容で置き換えてもOKです

### GitHubに保存するためのトークン(最初の1回)

1. GitHub右上のアイコン → **Settings → Developer settings → Personal access tokens → Fine-grained tokens → Generate new token**
2. **Expiration(有効期限)** は短めに(30日〜90日)
3. Repository access: **Only select repositories** で、このリポジトリだけを選ぶ
4. Permissions → **Contents: Read and write** にする(他の権限は付けない)
5. 生成されたトークンをコピーし、管理画面の「GitHubに保存」に貼り付ける
   - 「このタブを閉じるまで記憶する」にチェックすると、そのタブを開いている間だけ入力不要になります
   - トークンは**このブラウザの外にも、ブラウザの恒久的な保存領域にも残りません**(タブを閉じると消えます)
   - 使い終わったら、GitHubの同じ画面でトークンを削除(Revoke)すると安全です

> 管理画面のURLは誰でも開けますが、**トークンがない人は保存できません**(閲覧は可能)。
> トークンは他人に教えないでください。

## 地図の使いかた(利用者向けの機能)

- 背景: 地理院地図 / 航空写真
- 地番検索: 「大字」を選び、地番を入力(全角・半角、ハイフンの違いは自動で吸収)
- レイヤー選択: カテゴリごとに開閉でき、カテゴリのチェックで中のレイヤーをまとめて表示/非表示
- 透明度スライダー、現在地、地図クリックで属性表示、GeoJSONダウンロード(許可したレイヤーのみ)
- **印刷**: 右上の「印刷」ボタンで印刷プレビューに入り、用紙(A4/A3)・向き(横/縦)・タイトル・凡例の有無を選んで印刷できます。
  縮尺の目安、凡例、参考図であることの案内、出典、利用規約のURLが、用紙の中に入ります(印刷の設定は「倍率100%」「背景のグラフィックをオン」)
- **案内帯・利用規約**: 画面の一番下に「この地図情報は、あくまでも参考図であり…」の案内帯が常に表示され、クリックすると利用規約(`terms.html`)が開きます

### 案内帯と利用規約の設定

- 管理画面の「全体設定」で、案内帯の表示/非表示・案内文、利用規約に載せる**運営者名・担当課・連絡先・制定日・追記事項**を設定します
- 利用規約の本文は `terms.html` にあります。**公開前に、運営者(自治体・組織)の法務担当などが内容を確認してください**。
  裁判管轄・個人情報・免責の範囲などは、組織の規定に合わせて `terms.html` を直接編集します

## 軽く動かすための工夫

- 表示範囲の区画だけ読み込み、使い終わった区画は自動で破棄
- 図形のクリック判定を使わず、クリック位置から計算(スクロールが軽くなります)
- 地番の文字は、拡大時・画面内で最大400件
- 変換結果は再利用され、変更のないデータは再変換されません

## 困ったとき

| 症状 | 確認すること |
|---|---|
| 地図が出ない・「設定の読み込みに失敗」 | Actionsタブで最後のビルドが緑か。Settings → Pages の Source が「GitHub Actions」か |
| レイヤーが追加されない | Actionsのログに「公開されないレイヤー」の表示がないか(座標系が EPSG:4326 でない、など) |
| ズームしても出ない | レイヤーの「表示を始めるズーム」を確認(大きいデータは拡大が必要) |
| 管理画面で保存できない | トークンの権限(Contents: Read and write)、ユーザー名・リポジトリ名 |
| 保存したのに変わらない | 反映まで数分かかります。Actionsタブで進み具合を確認 |

## セキュリティについて

### 守られていること(実装済み)

- ポップアップ・検索結果・凡例・地図上の文字は、データに `<script>` などが含まれていても動かないように処理しています
- ポップアップの「自由なHTML」は、許可したタグ(太字・表・リンクなど)だけが使え、スクリプトや画像は使えません。リンクは http/https のみです
- `config.json` の色・URL・ファイルパスは検証し、不正な値は無視します
- 地図ライブラリ(Leaflet)はビルド時に公式配布から取得して同梱し、公開サイトは外部のスクリプトを読み込みません(CSPで外部スクリプトを禁止)
- 管理画面は他のサイトに埋め込まれても動かないようにしています
- 管理用のトークンは、タブを閉じると消える領域にだけ置きます

### 運用で守ってほしいこと

1. **GitHubアカウントの2段階認証を有効にする**(最重要。アカウントを乗っ取られるとサイトを書き換えられます)
2. トークンは「このリポジトリだけ」「Contents: Read and write のみ」「有効期限つき」で作り、使い終わったら削除する
3. リポジトリの共同編集者(Collaborators)は必要な人だけにする
4. **「ダウンロード不可」は表示上の設定です**。公開サイトのデータは、URLを知っていれば誰でも取得できます。
   Publicリポジトリの `data/` にある元ファイルも誰でも見られます。**非公開にしたい情報は置かない**でください
5. 新しいデータを置く前に、属性(列)を確認する。管理画面の「データ変換 → 残す属性」で、
   **公開が必要な属性だけ**を残してください(所有者名・備考などは外す)。
   一度GitHubに置いたファイルは、あとで削除しても履歴に残ります
6. 地番図などの公開に問題がないか(法令・自治体の規定・提供元の利用条件)を確認し、出典表示は
   管理画面の「地図右下の出典表示」「出典」に書く

### 知っておくこと

- 閲覧者のIPアドレスなどは、地図の背景(国土地理院)に送られます
- GitHub Pagesは、アクセスが非常に多いサービスや、個人情報を扱うサービスには向きません
- 管理画面のURLは誰でも開けます。トークンがなければ保存できませんが、画面には属性名とサンプルが表示されます

## 注意

- 地理院タイルの利用規約(出典表示)に従ってください(画面右下に自動表示されます)。
- 地番図など個人に関わり得るデータを公開する際は、公開範囲・法令・自治体の規定を必ず確認してください。
  ダウンロードを許可すると、誰でもデータを入手できます。
- GitHub Pages(無料)の公開サイトの大きさは1GBまでです(現在のデータで約150MB)。
- Publicリポジトリに置いた `data` 内のファイルは、誰でも閲覧・ダウンロードできます。
